# Helm Full Concepts

Helm is a package manager for Kubernetes, it is used to simplify application deployment and management inside Kubernetes clusters.

Helm helps DevOps Engineers install, upgrade, configure, and manage Kubernetes applications easily.

Helm uses reusable templates called Charts to deploy applications.

Helm reduces the complexity of managing large Kubernetes YAML files manually.

Helm is widely used in Kubernetes environments, cloud-native applications, CI/CD pipelines, and microservices deployments.

## Why Helm is Used

Helm simplifies Kubernetes application deployment.

Helm manages complex Kubernetes configurations efficiently.

Helm supports reusable templates and configuration management.

Helm supports versioning and rollback functionality.

Helm improves deployment consistency across environments.

Helm integrates with CI/CD and GitOps workflows.

## What is Helm Chart

Helm Chart is a package containing Kubernetes resource templates and configurations.

Charts contain Deployments, Services, ConfigMaps, Secrets, and other Kubernetes resources.

Charts make applications reusable and portable across environments.

A Chart works like an installation package for Kubernetes applications.

## Helm Architecture

Helm Architecture mainly contains Helm CLI, Helm Charts, Repositories, and Kubernetes Cluster.

### Helm CLI

Helm CLI is the command-line tool used to interact with Helm.

Users install, upgrade, rollback, and manage applications using Helm commands.

### Helm Charts

Charts contain Kubernetes templates and configuration files.

Charts define how applications should be deployed inside Kubernetes.

### Helm Repository

Helm Repository stores and distributes Helm Charts.

Repositories work similarly to package repositories like APT or YUM.

Official public repository example:

```text id="jlwm1a"
https://artifacthub.io
```

### Kubernetes Cluster

Helm deploys resources directly into Kubernetes clusters using Kubernetes API Server.

## Helm Chart Structure

A Helm Chart contains multiple directories and files.

Example chart structure:

```text id="jlwm2b"
mychart/
  Chart.yaml
  values.yaml
  templates/
  charts/
```

### Chart.yaml

`Chart.yaml` contains chart metadata information.

Example:

```yaml id="jlwm3c"
apiVersion: v2
name: mychart
version: 1.0.0
```

### values.yaml

`values.yaml` stores configurable values used inside templates.

Example:

```yaml id="jlwm4d"
replicaCount: 2
image:
  repository: nginx
```

### templates Directory

The `templates/` directory contains Kubernetes YAML templates.

Templates use placeholders and dynamic variables.

### charts Directory

The `charts/` directory stores dependent subcharts.

```bash id="jlwm6f"

```

Add repository:

```bash id="jlwm7g"

```

Update repositories:

```bash id="jlwm8h"

```

List repositories:

```bash id="jlwm9i"
helm repo list
```

Search charts:

```bash id="jlwm0j"
helm search repo nginx
```

## Install Helm Chart

Install application using chart:

```bash id="jlwm1k"
helm install mynginx bitnami/nginx
```

This command deploys Nginx application into Kubernetes cluster.

List installed releases:

```bash id="jlwm2l"
helm list
```

## Helm Release

Release is a running instance of a Helm Chart inside Kubernetes cluster.

Each installation creates a unique release.

Helm tracks release history and versions.

## Upgrade Helm Release

Upgrade application:

```bash id="jlwm3m"
helm upgrade mynginx bitnami/nginx
```

Helm updates Kubernetes resources automatically.

## Rollback Helm Release

Rollback restores previous application version.

View release history:

```bash id="jlwm4n"
helm history mynginx
```

Rollback release:

```bash id="jlwm5o"
helm rollback mynginx 1
```

## Uninstall Helm Release

Remove deployed application:

```bash id="jlwm6p"
helm uninstall mynginx
```

## Create Helm Chart

Create new chart:

```bash id="jlwm7q"
helm create mychart
```

This command generates default chart structure automatically.

## Helm Templates

Helm templates generate dynamic Kubernetes YAML files.

Templates use Go templating syntax.

Example template variable:

```yaml id="jlwm8r"
replicas: {{ .Values.replicaCount }}
```

Helm replaces variables using values from `values.yaml`.

## Helm Values

Values customize application configuration during deployment.

Custom values file example:

```yaml id="’wini9s"
replicaCount: 3
service:
  type: LoadBalancer
```

Install using custom values:

```bash id="’wini0t"
helm install myapp ./mychart -f values.yaml
```

Override values directly:

```bash id="’wini1u"
helm install myapp ./mychart --set replicaCount=3
```

## Helm Dependency Management

Charts can depend on other charts.

Dependencies are defined in `Chart.yaml`.

Example dependency:

```yaml id="’wini2v"
dependencies:
  - name: mysql
    version: 9.0.0
```

Download dependencies:

```bash id="’wini3w"
helm dependency update
```

## Helm Hooks

Hooks execute actions during chart lifecycle events.

Hooks run before or after installation, upgrade, or deletion.

Example hook events are pre-install and post-upgrade.

## Helm Lint

Run lint:

```bash id="’wini4x"

```

## Helm Template Command

Generate Kubernetes YAML without deploying:

```bash id="’wini5y"

```

This command helps verify generated manifests.

## Helm Package

Package chart into compressed archive:

```bash id="’wini6z"

```

## Helm Repo Index

Create repository index file:

```bash id="’wini7a"
helm repo index .
```

## Helm with Kubernetes

Helm interacts directly with Kubernetes API Server.

Helm deploys Deployments, Services, Ingress, ConfigMaps, Secrets, and other Kubernetes resources automatically.

Helm simplifies complex multi-resource deployments.

## Helm with CI/CD

CI/CD tools like Jenkins use Helm for Kubernetes deployments.

Helm automates deployments in DevOps pipelines.

Argo CD can deploy Helm Charts directly from Git repositories.

## Helm Security

Sensitive information should not be stored directly inside Helm Charts.

Use Kubernetes Secrets for passwords and tokens.

Restrict repository access properly.

Verify chart sources before installation.

## Helm Best Practices

Use reusable and modular charts.

Keep values configurable using `values.yaml`.

Store charts in version control systems like Git.

Use separate values files for development, staging, and production.

Test charts before production deployment.

Use rollback functionality during deployment failures.

## Helm Advantages

Helm simplifies Kubernetes deployments.

Helm supports reusable templates and configurations.

Helm supports version control and rollback functionality.

Helm improves deployment consistency.

Helm reduces manual YAML management complexity.

Helm integrates easily with CI/CD and GitOps tools.

## Helm Limitations

Complex templates may become difficult to manage.

Debugging Helm templates can become challenging.

Improper values configuration may create deployment issues.

Large charts may become difficult to maintain without proper structure.

## Helm Workflow

Developer creates Helm Chart templates.

Values define application configuration.

Helm generates Kubernetes manifests dynamically.

Helm communicates with Kubernetes API Server.

Kubernetes deploys resources into the cluster.

Helm tracks release history and application versions.

Applications can be upgraded, rolled back, or removed using Helm commands easily.
