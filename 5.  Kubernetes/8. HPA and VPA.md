# HPA and VPA in Kubernetes

Kubernetes provides autoscaling mechanisms to automatically adjust resources based on workload demand.

HPA stands for Horizontal Pod Autoscaler, VPA stands for Vertical Pod Autoscaler.

Both are used to improve performance, scalability, and efficient resource utilization in Kubernetes clusters.

## What is HPA

HPA called Horizontal Pod Autoscaler automatically increases or decreases the number of Pods based on resource usage or custom metrics.

HPA performs horizontal scaling, it scales by adding or removing Pod replicas.

HPA commonly uses CPU utilization, memory usage, or custom metrics for scaling decisions.

HPA helps applications handle changing traffic loads automatically.

## HPA Working Process

HPA continuously monitors Pod metrics using Metrics Server.

HPA compares current metrics with target values.

If resource usage becomes higher than threshold, HPA increases Pod replicas.

If resource usage becomes lower than threshold, HPA decreases Pod replicas.

Kubernetes Scheduler places newly created Pods on available worker nodes.

## HPA Architecture Components

Metrics Server collects CPU and memory metrics from Pods and Nodes.

HPA Controller monitors metrics and scaling rules.

Deployment or ReplicaSet manages Pod replicas.

## Example HPA Workflow

Application receives high user traffic.

CPU usage increases above configured threshold.

HPA detects high CPU usage.

HPA increases Pod replicas automatically.

Traffic gets distributed across multiple Pods.

When traffic decreases, HPA reduces unnecessary Pods.

## HPA Example Command

Create HPA:

```bash id="jlwm1a"
kubectl autoscale deployment nginx-deployment \
--cpu-percent=50 \
--min=2 \
--max=10
```

This command creates HPA for deployment.

`--cpu-percent=50` means target CPU usage is 50%.

`--min=2` means minimum 2 Pods always run.

`--max=10` means maximum scaling limit is 10 Pods.

## Check HPA Status

View HPA details:

```bash id="’wini2b"
kubectl get hpa
```

Describe HPA:

```bash id="’wini3c"
kubectl describe hpa nginx-deployment
```

## HPA YAML Example

```yaml id="’wini4d"
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler

metadata:
  name: nginx-hpa

spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx-deployment

  minReplicas: 2
  maxReplicas: 10

  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```

## Advantages of HPA

HPA automatically handles traffic spikes.

HPA improves application availability and scalability.

HPA optimizes resource usage dynamically.

HPA reduces manual scaling work.

HPA works well for stateless applications.

## Limitations of HPA

HPA mainly scales Pods, not container resource sizes.

New Pods may take time to start during sudden traffic spikes.

Applications must support horizontal scaling properly.

## What is VPA

VPA called Vertical Pod Autoscaler automatically increases or decreases CPU and memory resources for Pods.

VPA performs vertical scaling, it scales by changing container resource limits and requests.

VPA adjusts Pod resource allocation instead of changing Pod count.

VPA helps optimize CPU and memory allocation dynamically.

## VPA Working Process

VPA monitors Pod resource usage continuously.

VPA recommends or updates CPU and memory values.

If resource usage changes significantly, VPA updates resource requests and limits.

Pods may restart to apply updated resources.

## VPA Components

VPA Recommender analyzes historical and current resource usage.

VPA Updater evicts Pods requiring updated resources.

VPA Admission Controller modifies Pod resource requests during creation.

## VPA Modes

### Off Mode

VPA only provides recommendations, it does not change resources automatically.

### Initial Mode

VPA sets resource requests only during Pod creation.

### Auto Mode

VPA automatically updates resource requests and recreates Pods when needed.

## VPA YAML Example

```yaml id="’wini5e"
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler

metadata:
  name: nginx-vpa

spec:
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx-deployment

  updatePolicy:
    updateMode: "Auto"
```

## Check VPA Recommendations

View VPA details:

```bash id="’wini6f"
kubectl describe vpa nginx-vpa
```

## Advantages of VPA

VPA optimizes CPU and memory allocation automatically.

VPA reduces resource wastage.

VPA improves performance for applications requiring stable Pod counts.

VPA simplifies resource tuning.

## Limitations of VPA

VPA may restart Pods during resource updates.

VPA is less suitable for highly dynamic traffic spikes.

VPA may conflict with HPA if both scale based on CPU and memory simultaneously.

## HPA vs VPA

HPA scales the number of Pods horizontally, VPA scales CPU and memory vertically.

HPA adds or removes Pods, VPA changes resource allocation for existing Pods.

HPA is best for handling traffic spikes, VPA is best for optimizing resource allocation.

HPA works well for stateless applications, VPA is useful for resource-intensive applications.

HPA improves scalability using replication, VPA improves efficiency using resource optimization.

## HPA and VPA Together

HPA and VPA can work together carefully in some environments.

Usually HPA handles scaling while VPA manages memory recommendations only.

Using both together on CPU scaling may create conflicts.

## Metrics Server

Metrics Server is required for HPA functionality.

Install Metrics Server:

```bash id="’wini7g"
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
```

Check metrics:

```bash id="’wini8h"
kubectl top pods
```

## Autoscaling Workflow

Application traffic increases.

Metrics Server collects resource metrics.

HPA or VPA analyzes resource usage.

HPA increases Pod replicas if needed.

VPA adjusts CPU and memory allocations if needed.

Kubernetes maintains desired application performance and resource efficiency automatically.
