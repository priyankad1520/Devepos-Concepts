# Kubernetes Full Concepts

Kubernetes called K8s is an open-source container orchestration platform used to automate deployment, scaling, management, and networking of containerized applications.

Kubernetes was originally developed by Google and is now maintained by the Cloud Native Computing Foundation.

Kubernetes manages containers running on multiple servers automatically.

Kubernetes is mainly used for microservices, cloud-native applications, container orchestration, CI/CD pipelines, and scalable deployments.

Kubernetes works commonly with Docker containers.

## What is Container Orchestration

Container Orchestration is the automated management of containers across multiple servers.

Orchestration handles deployment, scaling, networking, load balancing, monitoring, and self-healing automatically.

Kubernetes is one of the most popular container orchestration platforms.

## Why Kubernetes is Used

Kubernetes automates container deployment and scaling.

Kubernetes improves application availability and reliability.

Kubernetes automatically restarts failed containers.

Kubernetes distributes traffic using load balancing.

Kubernetes supports rolling updates and rollback functionality.

Kubernetes manages applications consistently across environments.

Kubernetes supports cloud-native and microservices architectures.

## Kubernetes Architecture

Kubernetes Architecture mainly contains Control Plane and Worker Nodes.

### Control Plane

Control Plane manages the entire Kubernetes cluster.

The Control Plane makes scheduling and management decisions.

Main Control Plane components are API Server, Scheduler, Controller Manager, and ETCD.

### API Server

API Server is the central communication component of Kubernetes.

All Kubernetes commands and requests go through the API Server.

The API Server exposes REST APIs for cluster management.

### ETCD

ETCD is a distributed key-value database storing Kubernetes cluster data and configurations.

ETCD stores cluster state, secrets, and resource information.

### Scheduler

Scheduler decides which Worker Node should run a Pod.

Scheduler checks CPU, memory, and resource availability before assigning Pods.

### Controller Manager

Controller Manager continuously monitors cluster state.

Controllers ensure actual cluster state matches desired cluster state.

Example controllers are Deployment Controller and Node Controller.

## Worker Node

Worker Nodes run application containers.

Worker Nodes contain Kubelet, Kube Proxy, and Container Runtime.

### Kubelet

Kubelet is an agent running on each worker node.

Kubelet communicates with the Control Plane and manages Pods.

### Kube Proxy

Kube Proxy manages networking rules and service communication inside the cluster.

### Container Runtime

Container Runtime runs containers inside Kubernetes.

Examples are containerd and CRI-O.

## Kubernetes Cluster

A Kubernetes Cluster is a group of Control Plane and Worker Nodes working together.

The cluster manages containerized applications automatically.

## Pod

Pod is the smallest deployable unit in Kubernetes.

A Pod contains one or more containers sharing networking and storage.

Containers inside the same Pod communicate using localhost.

Example Pod YAML:

```yaml id="jjlwm1"
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod

spec:
  containers:
    - name: nginx
      image: nginx
```

Create Pod:

```bash id="jlwm2k"
kubectl apply -f pod.yaml
```

List Pods:

```bash id="jlwm3j"
kubectl get pods
```

Describe Pod:

```bash id="jlwm4k"
kubectl describe pod nginx-pod
```

Delete Pod:

```bash id="jlwm5m"
kubectl delete pod nginx-pod
```

## ReplicaSet

ReplicaSet ensures a specified number of Pods are always running.

If a Pod fails, ReplicaSet automatically creates a new Pod.

## Deployment

Deployment manages ReplicaSets and Pods.

Deployment supports scaling, rolling updates, and rollback functionality.

Example Deployment YAML:

```yaml id="jlwm6p"
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
        - name: nginx
          image: nginx
```

Create Deployment:

```bash id="jlwm7q"
kubectl apply -f deployment.yaml
```

List Deployments:

```bash id="jlwm8r"
kubectl get deployments
```

Scale Deployment:

```bash id="jlwm9s"
kubectl scale deployment nginx-deployment --replicas=5
```

Rollback Deployment:

```bash id="jlwm0t"
kubectl rollout undo deployment nginx-deployment
```

## Service

Service exposes Pods for internal or external communication.

Services provide stable networking for dynamic Pods.

### ClusterIP

ClusterIP exposes service internally within the cluster.

### NodePort

NodePort exposes service externally using worker node ports.

### LoadBalancer

LoadBalancer exposes service using cloud provider load balancers.

### ExternalName

ExternalName maps service to external DNS names.

Example Service YAML:

```yaml id="jlwm1u"
apiVersion: v1
kind: Service
metadata:
  name: nginx-service

spec:
  selector:
    app: nginx

  ports:
    - port: 80
      targetPort: 80

  type: NodePort
```

## Namespace

Namespace logically separates resources inside a Kubernetes cluster.

Namespaces help organize environments like development, staging, and production.

List namespaces:

```bash id="jlwm2v"
kubectl get namespaces
```

Create namespace:

```bash id="jlwm3w"
kubectl create namespace dev
```

## ConfigMap

ConfigMap stores non-sensitive configuration data separately from applications.

Applications can read configuration dynamically from ConfigMaps.

## Secret

Secret stores sensitive data like passwords, API keys, and tokens securely.

Secrets are base64 encoded inside Kubernetes.

## Volume

Volumes provide persistent storage for Pods.

Volumes keep data safe even if containers restart.

## Persistent Volume

Persistent Volume called PV provides cluster-wide storage resources.

Persistent Volume Claim called PVC requests storage from Persistent Volumes.

## Ingress

Ingress manages external HTTP and HTTPS traffic routing into the cluster.

Ingress works with Ingress Controllers like NGINX Ingress Controller.

Ingress supports domain-based routing and SSL termination.

## Kubernetes Networking

Each Pod gets a unique IP address.

Pods communicate directly with each other inside the cluster.

Services provide stable communication endpoints.

Kube Proxy manages internal networking rules.

CNI called Container Network Interface provides networking plugins for Kubernetes.

Examples are Calico, Flannel, and Weave.

## Kubernetes Scheduling

Scheduler places Pods on worker nodes based on available resources.

Scheduling considers CPU, memory, affinity, taints, and tolerations.

## Taints and Tolerations

Taints prevent Pods from running on certain nodes.

Tolerations allow Pods to run on tainted nodes.

## Node Selector

Node Selector schedules Pods on specific nodes using labels.

Example:

```yaml id="jlwm4x"
nodeSelector:
  disktype: ssd
```

Horizontal Pod Autoscaler called HPA automatically scales Pods based on CPU or memory usage.

Example HPA:

```bash id="jlwm1e"

```

## Rolling Updates

Rolling Updates update applications gradually without downtime.

Kubernetes replaces old Pods with new Pods step by step.

## Self-Healing

Kubernetes automatically restarts failed containers and recreates failed Pods.

Kubernetes maintains desired application state continuously.

## Kubernetes Security

RBAC called Role-Based Access Control manages permissions inside the cluster.

Network Policies restrict Pod communication.

Secrets securely store sensitive information.

Namespaces isolate workloads logically.

TLS secures Kubernetes API communication.

## Helm

Helm simplifies Kubernetes application deployment using Charts.

## Kubernetes with Cloud Providers

Google Cloud provides GKE called Google Kubernetes Engine.

Managed Kubernetes services simplify cluster management.

## Kubernetes Advantages

Kubernetes automates deployment and scaling.

Kubernetes improves application availability and reliability.

Kubernetes supports self-healing and rolling updates.

Kubernetes supports microservices architecture.

Kubernetes works across cloud and on-premises environments.

Kubernetes improves resource utilization and scalability.

## Kubernetes Limitations

Kubernetes has a steep learning curve for beginners.

Cluster management can become complex in large environments.

Troubleshooting networking and storage issues may require advanced knowledge.

Improper configuration may create security risks.

## Kubernetes Workflow

Developer creates application code.

Docker Image is built from the application.

Image is pushed to container registry.

Kubernetes Deployment YAML defines desired application state.

Kubernetes Scheduler assigns Pods to worker nodes.

Pods run containers inside the cluster.

Services expose applications internally or externally.

Ingress manages external HTTP and HTTPS traffic routing.

Kubernetes continuously monitors and maintains application health automatically.
