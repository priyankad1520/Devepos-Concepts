# Git Full Concepts

Git is a Distributed Version Control System called DVCS, it is used to track changes in source code and manage collaboration between developers.

Git helps developers store code history, manage versions, and work together without overwriting each other’s changes.

Git is widely used in DevOps, software development, CI/CD pipelines, and infrastructure management.

Git was created by Linus Torvalds for Linux kernel development.

Git works locally on the developer system and also supports remote repositories like GitHub, GitLab, and Bitbucket.

## What is Version Control

Version Control is the process of tracking changes made to files over time.

Version control helps restore previous versions if mistakes happen.

Version control improves collaboration between multiple developers.

Git stores every change history using commits.

## Why Git is Used

Git tracks code changes efficiently.

Git allows multiple developers to work simultaneously.

Git supports branching and merging for parallel development.

Git provides rollback capability to restore previous code versions.

Git integrates with CI/CD tools like Jenkins and Argo CD.

Git supports distributed development environments.

## Git Architecture

Git mainly contains three areas called Working Directory, Staging Area, and Local Repository.

### Working Directory

Working Directory is the current project folder where files are created and modified.

Changes made in files first appear in the working directory.

### Staging Area

Staging Area called Index stores changes temporarily before committing them.

The `git add` command moves changes from working directory to staging area.

### Local Repository

Local Repository stores all commits and version history inside the `.git` directory.

The `git commit` command permanently saves changes into the repository history.

### Remote Repository

Remote Repository is a centralized repository hosted on platforms like GitHub.

Developers push and pull code changes between local and remote repositories.

## Git Repository

Repository called Repo is a storage location containing project files and Git history.

Initialize new repository:

```bash id="m11q77"

```

Clone existing repository:

```bash id="4k2h93"
git clone https://github.com/user/repo.git
```

The `.git` directory stores all repository metadata and commit history.

## Git Workflow

Developer modifies files in working directory.

Developer adds changes to staging area using `git add`.

Developer commits changes into local repository using `git commit`.

Developer pushes commits to remote repository using `git push`.

Other developers pull latest changes using `git pull`.

## Git Branching

Branch is an independent line of development in Git.

Branches allow developers to work on features separately without affecting the main codebase.

The default branch is usually `main` or `master`.

Create branch:

```bash id="g5y8e6"
git branch feature1
```

Switch branch:

```bash id="6uhg2m"
git checkout feature1
```

Create and switch branch together:

```bash id="0l7u6q"
git checkout -b feature1
```

List branches:

```bash id="8szwx4"
git branch
```

Delete branch:

```bash id="2uw7lv"
git branch -d feature1
```

## Git Merge

Merge combines changes from one branch into another branch.

Switch to main branch:

```bash id="vfq7uy"
git checkout main
```

Merge feature branch:

```bash id="8v2v4r"
git merge feature1
```

Merge conflicts happen when multiple developers modify the same lines of code.

Conflicts must be resolved manually before completing the merge.

## Git Rebase

Rebase moves commits from one branch onto another branch.

Rebase creates cleaner commit history compared to merge.

Example:

```bash id="rx4mjo"
git rebase main
```

## Git Reset

Git Reset removes commits or unstages changes.

Soft reset keeps file changes:

```bash id="w3xuhh"
git reset --soft HEAD~1
```

Hard reset removes changes completely:

```bash id="j3m7po"
git reset --hard HEAD~1
```

## Git Revert

Example:

```bash id="rjq8c8"

```


## Git Hooks

Git Hooks are scripts triggered automatically during Git events.

Hooks automate validation, testing, and formatting tasks.

Examples are pre-commit hooks and post-merge hooks.

## Git Internals

Git stores data using blobs, trees, and commits.

Blob stores file content.

Tree stores directory structure.

Commit stores metadata and snapshots of project state.

Git uses SHA hashing to uniquely identify commits.

## Git with GitHub

GitHub is a cloud-based Git repository hosting platform.

GitHub provides collaboration, pull requests, issues, actions, and code review features.

Push local repository to GitHub:

```bash id="0xbmow"
git push -u origin main
```

## Pull Requests

Pull Request called PR is a request to merge changes into another branch.

PRs help teams review code before merging.

PRs improve collaboration and code quality.

## Git Best Practices

Write meaningful commit messages.

Commit small logical changes frequently.

Use branches for feature development.

Pull latest changes before pushing code.

Avoid committing sensitive files like passwords and keys.

Use `.gitignore` properly.

Review code before merging pull requests.

## Git Advantages

Git provides fast version control operations.

Git allows rollback and recovery of code changes.

## Git Limitations

Git can become complex for beginners.

Large binary files are not handled efficiently.

Merge conflicts may become difficult in large projects.

Improper branching strategies may create confusion.

## Git Workflow in DevOps

Developer commits changes locally using Git.

Developer pushes code to GitHub or GitLab.

CI/CD tools like Jenkins automatically detect code changes.

Pipelines build, test, and deploy applications automatically.

Deployment tools like Argo CD synchronize Kubernetes deployments from Git repositories.
