# Git Commands Step-by-Step Process for a DevOps Engineer

Git is used by DevOps engineers for:

* Source code management
* CI/CD pipeline integration
* Infrastructure as Code (Terraform, Kubernetes YAML)
* Collaboration with developers
* Version control and rollback

---

### 1. Install Git
- **Check Git Version:** `git --version`
- **Install Git (Ubuntu/Linux):** `sudo apt update` and `sudo apt install git -y`

### 2. Configure Git (First Time Setup)
- **Set Username:** `git config --global user.name "Priyanka"`
- **Set Email:** `git config --global user.email "priyanka@gmail.com"`
- **Check Configuration:** `git config --list`

> **Why We Use This:** Git stores your name and email in every commit.

### 3. Create a New Repository
- **Create Folder:** `mkdir devops-project`
- **Move Into Folder:** `cd devops-project`
- **Initialize Git Repository:** `git init`

> What Happens?: Git creates a hidden `.git` folder to track changes.

### 4. Check Repository Status: 
`git status`
> Why We Use This. It Shows: Modified files, Untracked files, Staged files

### 5. Create a File
```
touch app.py` or `nano app.py
```

### 6. Add File to Staging Area
- **Add Single File:** `git add app.py`
- **Add All Files:** `git add .`
> Why We Use This: Moves files to staging area before commit.

### 7. Commit Changes
```
git commit -m "Added app.py file"
```
> Why We Use This: Saves snapshot/version of project.

### 8. View Commit History
```
git log
git log --oneline #One Line Format
```
- **

### 9. Connect GitHub Repository
- **Add Remote Repository:** `git remote add origin https://github.com/user/project.git`
- **Check Remote URL:** `git remote -v`
> Why We Use This: Connects local repository to GitHub.

### 10. Push Code to GitHub
- **Push Main Branch:** `git push -u origin main`
> What Happens?: Uploads local code to GitHub repository.

### 11. Clone Existing Repository
```bash
git clone https://github.com/user/project.git
```
> Why We Use This: Downloads repository from GitHub.

### 12. Pull Latest Changes
```bash
git pull origin main
```
> Why We Use This: Gets latest code from remote repository.

### 13. Create Branch
```bash
git branch feature-login
git checkout feature-login  # Switch Branch
git checkout -b feature-login # Create + Switch Together
```
> Why Branch?  Used for: New features, Bug fixes, Testing

### 14. Check Branches

```bash
git branch
```

### 15. Merge Branch
 ```bash
git checkout main # Move to Main Branch
git merge feature-login  # Merge Feature Branch
```
> What Happens?: Combines feature branch code into main branch.

### 16. Delete Branch

## 

```bash
git branch -d feature-login # Delete Local Branch
git push origin --delete feature-login # Delete Remote Branch
```
### 17. Check Differences
```bash
git diff # Compare Changes
git diff --staged # Compare Staged Changes
```
### 18. Undo Changes
```bash
git restore --staged app.py # Remove From Staging
git restore app.py # Discard Local Changes
```
### 19. Remove File
```bash
git rm file.txt
```
### 20. Rename File
```bash
git mv old.txt new.txt
```

### 21. Stash Changes
```bash
git stash # Save Temporary Changes
git stash list # View Stash
git stash apply # Restore Stash
```
> Why We Use This: Temporarily saves unfinished work.

### 22. View Remote Branches
```bash
git branch -r
```
### 23. Fetch Latest Changes
```bash
git fetch
```

### Difference Between Pull and Fetch
```
git fetch # Downloads changes only     
git pull  # Downloads + merges changes 
```
### 24. Reset Commands
```bash
git reset --soft HEAD~1 # Soft Reset
git reset --hard HEAD~1 # Hard Reset
```
> Why We Use This: Undo commits.

### 25. Revert Commit
```bash
git revert commit_id
```
> Why We Use This: Safely undo changes in shared repository.

### 26. Tagging (Used in Release Management)
```bash
git tag v1.0 # Create Tag
git push origin v1.0 # Push Tag
```
> Why DevOps Engineers Use Tags. Used for:  Production releases, Rollback versions, CI/CD deployments

# Real-Time DevOps Git Workflow

##### Step 1: Clone Project: `git clone https://github.com/company/project.git`
##### Step 2: Move Into Project: `cd project`
##### Step 3: Create Branch: `git checkout -b terraform-changes`
##### Step 4: Modify Files
Example: Dockerfile, Jenkinsfile, Kubernetes YAML, Terraform code
##### Step 5: Check Changes: `git status`
##### Step 6: Add Changes: `git add .`
##### Step 7: Commit Changes: `git commit -m "Updated Terraform configuration"`
##### Step 8: Push Branch: `git push origin terraform-changes`
##### Step 9: Create Pull Request (PR)
In GitHub: Compare changes, Review code, Merge to main branch
##### Step 10: Pull Latest Main Branch
```bash
git checkout main
git pull origin main
```

# Common Git Errors and Solutions

## 1. Authentication Failed
**Solution:** Use GitHub Personal Access Token (PAT).

## 2. Merge Conflict
**Solution:** Open conflicted file, Edit manually
```bash
Then:
git add .
git commit -m "Resolved merge conflict"
```
## 3. Detached HEAD
**Solution:** `git checkout main`

## 4. Permission Denied
**Solution:** Check SSH key: `ssh -T git@github.com`
