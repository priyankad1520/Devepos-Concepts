# Docker Full Concepts

Docker is a containerization platform, it is used to build, package, deploy, and run applications inside containers.

Docker helps developers and DevOps Engineers run applications consistently across different environments.

Docker solves the “it works on my machine” problem, because the application and dependencies are packaged together.

Docker is lightweight compared to Virtual Machines, because containers share the host operating system kernel.

Docker is mainly used for application deployment, microservices, CI/CD pipelines, testing, and cloud environments.

## What is Container

A Container is an isolated environment used to run applications with required dependencies.

Containers package application code, libraries, runtime, and configurations together.

Containers are lightweight and fast, because they do not require a separate operating system.

Containers share the host operating system kernel.

Containers provide portability, applications run the same in development, testing, and production environments.

## Docker vs Virtual Machine

Virtual Machines use a Hypervisor and each VM contains a separate Guest Operating System.

Containers share the host operating system kernel, Virtual Machines do not share kernels.

Containers are lightweight and start quickly, Virtual Machines are heavier and slower.

Containers consume less memory and CPU compared to Virtual Machines.

Virtual Machines provide full OS isolation, containers provide process-level isolation.

## Docker Architecture

Docker Architecture follows a client-server model.

Main components are Docker Client, Docker Daemon, Docker Engine, Docker Images, Containers, Registry, Networking, and Storage.

Docker Client is used to execute Docker commands.

Docker Daemon called `dockerd` manages images, containers, networks, and volumes.

Docker Engine is the core runtime environment of Docker.

Docker Registry stores Docker images, Docker Hub is the default public registry.

Docker Containers are running instances of Docker Images.

Docker uses `containerd` and `runc` internally for container lifecycle management.

## Docker Installation

Docker can be installed on Linux, Windows, and macOS systems.

Docker Engine is commonly installed on Linux servers.

Example installation on Ubuntu:

```bash
sudo apt update
sudo apt install docker.io -y
```

Start Docker service:

```bash
sudo systemctl start docker
```

Enable Docker during boot:

```bash
sudo systemctl enable docker
```

Check Docker version:

```bash
docker --version
```

Check Docker service status:

```bash
systemctl status docker
```

## Docker Images

Docker Image is a read-only template used to create containers.

Images contain application code, dependencies, libraries, environment variables, and configurations.

Images are built using Dockerfiles.

Docker images use layered architecture, each Dockerfile instruction creates a new layer.

Image layers are cached and reusable.

List local images:

```bash
docker images
```

Pull image from Docker Hub:

```bash
docker pull nginx
```

Remove image:

```bash
docker rmi nginx
```

## Docker Containers

Docker Container is a running instance of an image.

Containers run applications in isolated environments.

Run container:

```bash
docker run nginx
```

Run container in detached mode:

```bash
docker run -d nginx
```

Run container with custom name:

```bash
docker run --name mynginx nginx
```

List running containers:

```bash
docker ps
```

List all containers:

```bash
docker ps -a
```

Stop container:

```bash
docker stop container_id
```

Start container:

```bash
docker start container_id
```

Restart container:

```bash
docker restart container_id
```

Delete container:

```bash
docker rm container_id
```

## Dockerfile

Dockerfile is a text file containing instructions to build Docker Images automatically.

Dockerfile helps automate image creation.

Basic Dockerfile example:

```Dockerfile
FROM ubuntu
RUN apt update
RUN apt install nginx -y
CMD ["nginx", "-g", "daemon off;"]
```

Build image from Dockerfile:

```bash
docker build -t myimage .
```

## Important Dockerfile Instructions

`FROM` defines the base image.

`RUN` executes commands during image build.

`CMD` defines default command executed when container starts.

`ENTRYPOINT` defines fixed executable for the container.

`COPY` copies files from host to image.

`ADD` copies files and supports URL extraction.

`WORKDIR` sets working directory inside container.

`ENV` defines environment variables.

`EXPOSE` documents container listening ports.

`VOLUME` creates persistent storage mount points.

## Docker Networking

Docker networking allows communication between containers and external systems.

Docker automatically creates virtual networks for containers.

Bridge Network is the default Docker network.

Host Network allows container to use host network directly.

None Network disables networking for the container.

Overlay Network is used for multi-host communication in Docker Swarm.

List networks:

```bash
docker network ls
```

Create network:

```bash
docker network create mynetwork
```

Run container in network:

```bash
docker run --network=mynetwork nginx
```

## Docker Volumes

Docker Volumes provide persistent storage for containers.

Data inside volumes remains even if the container is deleted.

Volumes are used for databases and persistent applications.

Create volume:

```bash
docker volume create myvolume
```

List volumes:

```bash
docker volume ls
```

Mount volume:

```bash
docker run -v myvolume:/data nginx
```

Bind Mount connects host directories directly into containers.

Example:

```bash
docker run -v /host/path:/container/path nginx
```

## Docker Registry

Docker Registry stores and distributes Docker images.

Docker Hub is the default public registry.

Private registries are used inside organizations.

Login to Docker Hub:

```bash
docker login
```

Push image to registry:

```bash
docker push username/image
```

Pull image from registry:

```bash
docker pull username/image
```

## Docker Logs and Monitoring

Check container logs:

```bash
docker logs container_id
```

Check running processes inside container:

```bash
docker top container_id
```

Check container resource usage:

```bash
docker stats
```

Inspect container details:

```bash
docker inspect container_id
```

## Docker Exec

Docker Exec runs commands inside running containers.

Access container terminal:

```bash
docker exec -it container_id bash
```

Run command inside container:

```bash
docker exec container_id ls
```

## Docker Compose

Docker Compose manages multi-container applications using YAML files.

Docker Compose helps run databases, backend, frontend, and monitoring tools together.

Example `docker-compose.yml`:

```yaml
version: '3'
services:
  web:
    image: nginx
    ports:
      - "80:80"
```

Start services:

```bash
docker compose up -d
```

Stop services:

```bash
docker compose down
```

## Docker Swarm

Docker Swarm is Docker’s native orchestration tool.

Swarm manages multiple Docker hosts as a cluster.

Swarm supports scaling, load balancing, and high availability.

Initialize swarm:

```bash
docker swarm init
```

List swarm nodes:

```bash
docker node ls
```

## Docker Security

Docker uses namespaces for process isolation.

Docker uses cgroups to limit CPU and memory usage.

Containers should avoid running as root user for security.

Images should be scanned for vulnerabilities using tools like Trivy.

Secrets and sensitive data should not be stored directly inside images.

Use minimal base images to reduce attack surface.

## Docker Resource Management

Docker allows limiting CPU and memory for containers.

Limit memory usage:

```bash
docker run -m 512m nginx
```

Limit CPU usage:

```bash
docker run --cpus="1.5" nginx
```

## Docker Cleanup Commands

Remove stopped containers:

```bash
docker container prune
```

Remove unused images:

```bash
docker image prune
```

Remove unused volumes:

```bash
docker volume prune
```

Remove unused networks:

```bash
docker network prune
```

Remove all unused Docker resources:

```bash
docker system prune
```

## Advantages of Docker

Docker provides portability across environments.

Docker improves deployment speed and consistency.

Docker reduces infrastructure overhead.

Docker supports scalability and microservices architecture.

Docker improves resource efficiency compared to Virtual Machines.

Docker simplifies dependency management.

## Limitations of Docker

Containers share the host kernel, they do not provide full OS isolation like Virtual Machines.

Misconfigured containers may create security risks.

Managing large-scale container environments manually becomes difficult without orchestration tools like Kubernetes.

Persistent storage management can become complex in distributed environments.

## Docker Workflow

Developer writes application code.

Developer creates Dockerfile.

Docker builds image from Dockerfile.

Image is stored in Docker Registry.

Docker pulls image from registry when needed.

Docker creates containers from the image.

Containers run applications in isolated environments.

Docker manages networking, storage, and resource allocation for containers.
