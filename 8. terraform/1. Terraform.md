# Terraform Full Concepts

Terraform is an open-source Infrastructure as Code called IaC tool used to create, manage, and automate infrastructure resources using code.

Terraform is developed by HashiCorp.

Terraform helps DevOps Engineers automate cloud infrastructure provisioning and management.

Terraform supports multiple cloud providers like Amazon Web Services, Microsoft Azure, and Google Cloud.

Terraform can create servers, networks, Kubernetes clusters, storage, databases, and many other resources automatically.

Terraform uses declarative language called HCL called HashiCorp Configuration Language.

## What is Infrastructure as Code

Infrastructure as Code called IaC is the process of managing infrastructure using code instead of manual configuration.

IaC improves automation, consistency, scalability, and version control.

Terraform stores infrastructure definitions in `.tf` files.

## Why Terraform is Used

Terraform automates infrastructure creation and management.

Terraform reduces manual configuration work.

Terraform supports reusable infrastructure templates.

Terraform provides version-controlled infrastructure changes.

Terraform supports multi-cloud environments.

Terraform helps maintain consistent infrastructure across environments.

## Terraform Architecture

Terraform Architecture mainly contains Terraform Core and Providers.

### Terraform Core

Terraform Core reads configuration files and manages infrastructure lifecycle.

Terraform Core creates execution plans and manages state files.

Terraform Core communicates with providers using APIs.

### Providers

Providers are plugins used to interact with cloud platforms and services.

Providers allow Terraform to manage resources in AWS, Azure, Google Cloud, Kubernetes, Docker, and many other platforms.

Example provider block:

```hcl id="6v17c0"
provider "aws" {
  region = "us-east-1"
}
```

## Terraform Workflow

Developer writes Terraform configuration files.

Terraform initializes providers and modules.

Terraform creates execution plan showing proposed changes.

Terraform applies configurations using provider APIs.

Cloud resources are created or updated automatically.

Terraform stores infrastructure state in state files.

## Terraform Files

Terraform uses `.tf` files to define infrastructure.

Common Terraform files are `main.tf`, `variables.tf`, `outputs.tf`, and `terraform.tfvars`.

### main.tf

`main.tf` contains main infrastructure resources.

### variables.tf

`variables.tf` stores input variable definitions.

### outputs.tf

`outputs.tf` displays important output values after deployment.

### terraform.tfvars

`terraform.tfvars` stores variable values separately.

## Basic Terraform Configuration

Example AWS EC2 instance creation:

```hcl id="9rdmfc"
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "myserver" {
  ami           = "ami-123456"
  instance_type = "t2.micro"
}
```

## Terraform State File

Terraform stores infrastructure details in `terraform.tfstate`.

State file maps Terraform configurations to actual infrastructure resources.

Terraform uses state files to detect changes and manage resources.

State files are very important and should be stored securely.

## Remote State

Remote State stores Terraform state files in shared storage like S3 buckets.

Remote state improves collaboration and prevents conflicts.

Example backend configuration:

```hcl id="zyq3t8"
terraform {
  backend "s3" {
    bucket = "terraform-state"
    key    = "prod/terraform.tfstate"
    region = "us-east-1"
  }
}
```

## Terraform Modules

Modules are reusable Terraform configuration blocks.

Modules improve code reusability and maintainability.

Terraform Registry provides public reusable modules.

Example module usage:

```hcl id="26gx4y"
module "vpc" {
  source = "terraform-aws-modules/vpc/aws"
}
```

## Terraform Provisioners

Provisioners execute scripts or commands after resource creation.

Example local-exec provisioner:

```hcl id="fxxswd"
provisioner "local-exec" {
  command = "echo Server Created"
}
```

Provisioners should be used carefully because they reduce declarative behavior.

## Terraform Dependency Management

Terraform automatically handles resource dependencies.

Terraform creates resources in correct order based on references.

Explicit dependency example:

```hcl id="6i2cc4"
depends_on = [aws_vpc.main]
```

## Terraform Lifecycle Rules

Lifecycle rules control resource behavior during updates.

Example:

```hcl id="6kkr1e"
lifecycle {
  prevent_destroy = true
}
```

`prevent_destroy` prevents accidental resource deletion.

## Terraform Data Sources

Data Sources fetch information from existing infrastructure resources.

Example:

```hcl id="jlwm1n"
data "aws_ami" "ubuntu" {
  most_recent = true
}
```

## Terraform Security

Sensitive credentials should not be hardcoded in Terraform files.

Use environment variables or secret management tools for credentials.

Restrict access to Terraform state files.

Use version control systems like Git for Terraform code management.

Use least privilege IAM permissions for Terraform execution.

## Terraform Best Practices

Use modules for reusable infrastructure.

Store state files remotely.

Use version control for Terraform code.

Separate environments using workspaces or folders.

Avoid hardcoding secrets in code.

Use `terraform plan` before `terraform apply`.

Review infrastructure changes carefully before deployment.

## Terraform Advantages

Terraform supports multi-cloud infrastructure management.

Terraform provides Infrastructure as Code automation.

Terraform improves consistency and scalability.

Terraform supports reusable modules.

Terraform integrates with DevOps and CI/CD pipelines.

## Terraform Limitations

Terraform state management can become complex in large environments.

Terraform may require manual handling for some cloud-specific features.

Improper state file management may cause infrastructure conflicts.

Provisioners reduce declarative behavior and should be minimized.

CI/CD tools like Jenkins execute Terraform pipelines.
